# LiROSa

## Overview

This project implements a differential drive mobile robot using ROS 2, with its robot description defined in URDF and its teleoperation enabled by `ros2_control`. The robot consists of a LiDAR sensor that is used for 2D SLAM

The robot is simulated in Gazebo, while RViz is used for visualization and monitoring. Keyboard teleoperation allows the robot to navigate through the simulated environment, and SLAM Toolbox is used to generate an occupancy grid map using laser scan data as the robot explores its surroundings.

The Gazebo world can also be customized to simulate the robot in different environments.

## Features

- **Robot Modeling:** Differential drive robot described using URDF.
- **Robot Control:** Wheel velocity control configured using `ros2_control`.
- **Simulation:** Robot spawned in Gazebo with a customizable world.
- **Visualization:** Robot model, TF frames, laser scans, and occupancy grid map displayed in RViz.
- **Keyboard Teleoperation:** Control the robot using `teleop_twist_keyboard`.
- **SLAM:** Generate an occupancy grid map using SLAM Toolbox.
- **Map Saving:** Save the generated map for autonomous navigation.

## Prerequisites

The following software and ROS 2 packages are required:

- ROS 2
- Gazebo compatible with the installed ROS 2 distribution
- RViz2
- `ros2_control`
- `ros2_controllers`
- SLAM Toolbox
- `teleop_twist_keyboard`

Ensure that the ROS 2 environment is sourced before building or launching the project.

## Build and Launch

### 1. Build the Package

Navigate to your ROS 2 workspace:

```bash
cd ~/ros2_ws
```

Build the package:

```bash
colcon build --packages-select <package_name>
```

Source the workspace:

```bash
source install/setup.bash
```

### 2. Launch the Simulation

Run the launch file:

```bash
ros2 launch <package_name> gazebo.launch.py
```

This launches the Gazebo simulation and RViz, with the robot and SLAM configuration loaded.

## RViz Configuration

In RViz2, configure the following displays:

- **TF:** Visualize the robot's coordinate frames.
- **RobotModel:** Set the robot description source to `robot_description`.
- **LaserScan:** Set the topic to `/scan`.
- **Map:** Set the topic to `/map`.

Once configured, RViz displays the robot model, coordinate frames, laser scan data, and the occupancy grid map generated by SLAM Toolbox.

## Teleoperation

Open a new terminal, source the ROS 2 environment and workspace if required, and run:

```bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -r cmd_vel:=/diff_drive_controller/cmd_vel_unstamped
```

Use the keyboard controls shown in the terminal to move the robot around the Gazebo world.

As the robot explores its surroundings, laser scan data is processed by SLAM Toolbox to incrementally build the occupancy grid map.

## Saving the Map

Once the robot has explored the desired area and the occupancy grid is visible in RViz, open a new terminal and run:

```bash
ros2 run nav2_map_server map_saver_cli -f ~/ros2_ws/src/<package_name>/maps/my_robot_map
```

This saves the map to files such as:

- `my_robot_map.yaml` — Map metadata.
- `my_robot_map.pgm` — Occupancy grid image.

The saved map can be used later for autonomous navigation.

## Customizing the Gazebo World

The simulation environment can be modified to test the robot in different surroundings.

1. Create or edit a world in Gazebo.
2. Save the world as an SDF file (`.sdf`) inside the `worlds/` directory.
3. Update the world file path in `launch/gazebo.launch.py` to use your custom world:

```python
world_file = os.path.join(
    get_package_share_directory('my_robot_description'),
    'worlds',
    'slam_world.sdf'  # Replace with your own world filename
)
```

Replace `slam_world.sdf` with the filename of your custom world, keeping it inside the `worlds/` directory.4. Relaunch the simulation to load the modified environment.

4. This allows the robot to explore and map different simulated environments without changing its core URDF model.
